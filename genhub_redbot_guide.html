🚀 GeneralsHub Bot & GenHub Cog Documentation

A specialized GitHub-to-Discord real-time orchestration engine built on top of RedBot 3.5.24 (discord.py 2.7.1). It captures repository events, creates structured forum threads, manages status tags, synchronizes comments, and eliminates notification spam.

🟢 Version: RedBot 3.5.24
🌐 Webhook Port: 0.0.0.0:8080
📦 Active Cogs: 23 Loaded
⚡ Rate Limiter: Adaptive Backoff
🔔 Active Notification Policy: Role mentions (@Contributor) are exclusively triggered when a New PR is Opened or an existing PR is Merged. Issues, closed unmerged PRs, review comments, and reconciliation updates generate threads cleanly without ping spam.

⌨️ GenHub Command Reference

All bot management commands can be executed by server owners in Discord using the ! prefix or via slash command.

🔍
Command Arguments Description Action
!genhub showconfig None Displays active webhook ports, forum IDs, tracked repos, and token status
!genhub reconcile [repo_name] Scans GitHub API and synchronizes all open PRs, issues, and comments
!genhub addrepo <owner/repo> Adds a repository to the tracked allowlist (e.g., community-outpost/GenHub)
!genhub removerepo <owner/repo> Removes a repository from the tracked allowlist
!genhub issuesforum <forum_id> Sets the Forum channel ID for GitHub Issues (github-issues-feed)
!genhub prsforum <forum_id> Sets the Forum channel ID for Pull Requests (pull-requests-feed)
!genhub logchannel <channel_id> Sets the error and alert logging channel (genhub-chat)
!genhub issuesfeedchat <channel_id> Sets the text channel for Issues chat feed notifications
!genhub prsfeedchat <channel_id> Sets the text channel for PRs chat feed notifications
!genhub contributorrole <role_id> Sets the role ID to tag on new PR opens and merges
!genhub token <token> Configures the GitHub API Personal Access Token
!genhub testrepo <owner/repo> Tests API reachability and permissions for a repository
!genhub clearcache None Clears in-memory thread cache to force fresh lookups
/genhubconfig Slash UI Modal interface to autofill and configure all parameters at once

🔄 Reconciliation & Rate Limiter Engine

🛡️ Open PR Filtering Rule

Reconciliation only fetches and creates threads for active OPEN PRs. Historical closed and merged pull requests are ignored during thread generation to maintain a lean, clean forum layout.

  • Zero clutter from months of closed PRs
  • Existing closed threads are safely preserved
  • Tags are synced dynamically
⏳ Exponential Rate Limiting

The built-in RateLimiter tracks GitHub API response headers (X-RateLimit-Remaining and X-RateLimit-Reset) and paces requests with automatic exponential backoff.

  • 0.75s minimum interval between calls
  • Automatic sleep when approaching limits
  • Prevents 403 Secondary Rate Limit errors
